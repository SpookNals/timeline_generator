# CV Timeline Generator

A small cross-platform (Windows/macOS/Linux) desktop app for building a
vertical timeline (studies, jobs, projects, ...) and exporting it as a
high-resolution PNG image, for example to drop into a CV or portfolio.

Built with [Rust](https://www.rust-lang.org/) and [egui](https://github.com/emilk/egui)/[eframe](https://github.com/emilk/egui/tree/master/crates/eframe).

## Features

- Add, edit, and delete timeline entries ("blocks"), each with a title, an
  optional subtitle, a start and end date (year + month), and a color.
- Entries are drawn as colored bars along a vertical time axis, alternating
  left/right, with their label placed alongside and connected by a thin
  leader line - so a label is never limited by how much text fits inside a
  bar.
- Overlapping periods automatically get their own lane so they don't visually
  collide, and their labels are kept from overlapping each other too.
- The canvas grows taller for a longer time range instead of squeezing
  everything into a fixed size, and the preview scrolls vertically.
- Save/open a project as JSON, so you can come back and keep editing it.
- Export the timeline as a PNG at a fixed, print-quality resolution.

## Running it

You'll need a [Rust toolchain](https://rustup.rs/) installed.

```
cargo run --release
```

The first build takes a while (it pulls in and compiles the GUI toolchain);
later builds are fast.

## Using the app

- **Timeline settings** (top of the left panel): the overall start/end year
  shown on the axis.
- **Blocks**: the list of entries already on the timeline. Click one to edit
  it, or use "Delete" to remove it.
- **Add block / Edit block**: title, optional subtitle, start/end year and
  month, and a color. "Add block" (or "Save changes" while editing) applies
  it to the timeline.
- **Save project / Save as... / Open project**: store or reload your entries
  as a `.json` file.
- **Export as PNG**: renders the current timeline to a PNG file at a fixed
  resolution, independent of the app window size.

## How it's put together

- `src/model.rs` - the plain data model (`Timeline`, `TimelineBlock`) plus
  the year/month helpers, and (de)serialization for the save/open format.
- `src/render.rs` - the single source of truth for how a timeline is laid
  out and drawn (lane assignment for overlapping periods, label placement,
  colors), written against a small `Canvas` trait so it doesn't care whether
  it's drawing to the screen or to an image.
- `src/ui.rs` - the egui-based UI: the toolbar, the editing panel, and the
  live preview (which implements `Canvas` by drawing through an
  `egui::Painter`).
- `src/export.rs` - implements the same `Canvas` trait on top of an in-memory
  image buffer, so `export_png` reuses the exact same rendering code as the
  live preview, just rasterized to a file instead of the screen. It draws
  text with a font read directly from the OS at export time (rather than one
  bundled into the app) - it tries a short list of common font file
  locations for the current OS (`FONT_CANDIDATES` in that file) and picks
  the first one it can find; on an unusual setup where none of them exist,
  exporting will fail with an error naming the paths it tried.
- `src/main.rs` - application entry point and window setup (including the
  app icon).

## The icon

`assets/icon.png` and `assets/icon.ico` are pixel-art generated by
`examples/gen_icon.rs` rather than drawn by hand. To change it, edit the
shapes/colors in that file and regenerate both files with:

```
cargo run --example gen_icon
```

`assets/icon.png` is embedded in the app and shown as the window/taskbar icon
while it's running; `assets/icon.ico` is embedded into the `.exe` itself (via
`build.rs`, on Windows only) so it also shows up in File Explorer and on a
desktop shortcut before the app is launched. If you change `icon.ico`, do a
full rebuild (`cargo build --release`) so the new icon gets embedded.
